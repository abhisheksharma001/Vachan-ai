# 13 — Frontend Architecture

The Vachan.ai frontend is a **Next.js 14 App Router** application written in TypeScript. It implements the public marketing site and the authenticated **Mirror** app where users create personas, capture writing samples, and chat with clones.

---

## Overview

```
app/
├── layout.tsx            # Root layout: fonts, metadata, global providers
├── globals.css           # Tailwind v4 tokens + Sandy+Coral design system
├── (marketing)/          # Public pages (landing, open-source)
├── (app)/                # Authenticated app shell (dashboard, mirror, personas, settings)
└── api/                  # Next.js BFF route handlers (talk to FastAPI)

components/
├── ui/                   # shadcn/ui base components (Button, Card, Input, etc.)
├── vachan/               # Domain-specific components (PersonaCard, ChatBubble, FidelityRing)
└── providers.tsx         # React Query + Tooltip + Toaster providers

lib/
├── api.ts                # Browser-side React Query hooks + fetch helpers
├── backend.ts            # Server-only backend client (dev token, no CORS)
├── types.ts              # Shared TypeScript types
└── utils.ts              # cn() and other helpers
```

---

## Route groups

We use Next.js route groups to separate layouts without adding path segments.

### `(marketing)`

Public, unauthenticated pages:

- `/` — landing page
- `/open-source` — open-source information

These pages use `app/(marketing)/layout.tsx`, which renders a top navigation and footer with the Sandy+Coral marketing chrome.

### `(app)`

Authenticated product shell:

- `/dashboard` — overview
- `/personas` and `/personas/[id]` — persona management
- `/conversations` and `/conversations/[id]` — chat history
- `/mirror` — the live clone chat
- `/settings` — profile and organization

These pages use `app/(app)/layout.tsx`, which renders the `AppSidebar`, top header, and the main content area.

## Design system

### Tailwind v4 + shadcn/ui

The project uses **Tailwind CSS v4** with the new `@theme` and `@import` syntax. `shadcn/ui` provides accessible base components styled with the project tokens.

### Sandy + Coral tokens

All colors live in `frontend/app/globals.css`:

- **Sand** (`sand-50` to `sand-500`) — backgrounds, surfaces, muted text
- **Coral** (`coral-300` to `coral-700`) — primary actions, focus rings, accents
- **Ink** (`ink-900`, `ink-700`, `ink-500`) — text hierarchy
- **Semantic tokens** — `background`, `foreground`, `primary`, `secondary`, `border`, `ring`

Use the semantic tokens first; reach for brand tokens only when the semantic mapping is not enough. Never hardcode hex values in components.

### Typography

- **Display / headings**: Fraunces (`font-display`)
- **Body**: Inter (`font-sans`)
- **Mono**: JetBrains Mono (`font-mono`)

### Radius and shadows

Use the tokenized radii (`radius-sm`, `radius-md`, `radius-lg`, `radius-pill`) and shadows (`shadow-sm`, `shadow-md`, `shadow-lg`) from `globals.css`.

## Data fetching: React Query + BFF pattern

### Browser → Next.js BFF → FastAPI

The browser never calls the FastAPI backend directly. Instead:

1. **React Query hooks** in `lib/api.ts` call local Next.js route handlers under `app/api/**`.
2. **Route handlers** import `backend()` from `lib/backend.ts`, which runs only on the server.
3. `lib/backend.ts` mints a short-lived dev token and forwards the request to FastAPI.

This keeps the auth secret and backend URL out of the client bundle and avoids CORS.

### Query keys

Use the exported `keys` object from `lib/api.ts` so invalidation stays consistent:

```ts
import { keys, usePersonas } from "@/lib/api";

const { data: personas } = usePersonas();

// Invalidate after a mutation
queryClient.invalidateQueries({ queryKey: keys.personas });
```

### Server-only safety

`lib/backend.ts` must only be imported from route handlers (`app/api/**/route.ts`). Client components import `lib/api.ts` instead.

## Component conventions

### Base components (`components/ui/`)

- Auto-generated by `shadcn/ui`.
- Keep them generic and unmodified unless the design system changes.
- Use `className={cn("...", className)}` to allow callers to extend styles.

### Domain components (`components/vachan/`)

- Build higher-level features here (e.g. `PersonaCard`, `ChatBubble`, `FidelityRing`).
- Compose from `components/ui/*`.
- Keep business logic in hooks; components should mostly render props.

### Client vs server

- Mark client components with `"use client"` when using React hooks, browser APIs, or event handlers.
- Keep pages server by default; extract interactive pieces into client components in `components/vachan/`.

## How to add a new page

1. **Pick the route group**
   - Public page → `app/(marketing)/new-page/page.tsx`
   - Authenticated page → `app/(app)/new-page/page.tsx`

2. **Use the existing layout**
   - `(marketing)` pages get the marketing header/footer automatically.
   - `(app)` pages get the sidebar and app header automatically.

3. **Fetch data via hooks**
   - Add a fetch function and hook in `lib/api.ts` if one does not exist.
   - Use React Query hooks in the client component or call the backend from a server component route handler.

4. **Add navigation links**
   - Marketing nav: `app/(marketing)/layout.tsx`
   - App sidebar: `components/vachan/AppSidebar.tsx`

---

## How to add a new component

1. **If it is a generic primitive**, add it to `components/ui/` via shadcn (e.g. `npx shadcn add select`).
2. **If it is domain-specific**, create it in `components/vachan/MyComponent.tsx`.
3. **Use tokens**: `bg-sand-50`, `text-ink-900`, `border-sand-300`, `text-coral-500`.
4. **Export named component**. Import with the `@/components/vachan/MyComponent` alias.

Example:

```tsx
// components/vachan/MyComponent.tsx
"use client";

import { cn } from "@/lib/utils";

export function MyComponent({ className }: { className?: string }) {
  return (
    <div className={cn("rounded-md border border-sand-300 bg-sand-100 p-4", className)}>
      <p className="text-ink-700">Hello from Vachan</p>
    </div>
  );
}
```
